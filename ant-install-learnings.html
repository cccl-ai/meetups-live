Installing ant

macOS · brew → gh → uv → python
A one-line install surfaced four unrelated gotchas — none of them about ant. The pattern: tools assume a wired-up environment, and macOS upgrades quietly unwire it.

What broke, in order

Four unrelated cliffs to fall off

01
gh auth ≠ git auth
gh auth login doesn't configure git's HTTPS credential helper. Brew tap clones via plain git and hit a username prompt. Fix: gh auth setup-git.
02
anthropics has an 's'
The GitHub org is anthropics, not anthropic. The docs say anthropics/tap/ant; the typo returns a 404 that looks like an access error.
03
uv add needs a project
No pyproject.toml means no uv add. Either uv init first, or fall back to uv pip install inside a venv.
04
Brew Python rots on OS upgrade
platform.mac_ver() returning empty is the tell — Homebrew's Python wasn't rebuilt for the new macOS. Reinstall, or stop depending on it.
05
Shell vars vanish across sessions
The quickstart's $AGENT_ID / $ENVIRONMENT_ID exports don't survive a new terminal. Empty vars → API 400 with a null id. Recover via ant beta:agents list then re-export.
06
curl -s hides the error body
A bare error: 400 tells you nothing. Use -i or drop -s with --fail-with-body so the API's actual rejection message comes through.
07
Trust the SDK, not the curl snippet
Quickstart bash showed /sessions/$ID/stream — 404. SDKs all use sessions.events.stream, i.e. /sessions/$ID/events/stream. That worked. Doc bash examples drift; SDK paths are the source of truth.
Where Python comes from

Two ways to get a Python uv can use

Fragile
Homebrew Python
/opt/homebrew/bin/python3
  • Breaks silently when macOS major version changes
  • One global version — hard to pin per project
  • Shared with everything else brew installs
  • Fix requires brew reinstall python@3.x after each OS bump
Chosen
uv-managed Python
uv init --python 3.13
  • uv downloads and pins its own interpreter
  • Per-project version recorded in pyproject.toml
  • Independent of brew, system Python, and OS upgrades
  • No reinstall dance after macOS bumps
The realisation

Don't fight the Python that broke.

If brew's Python is broken, why is brew's Python in the loop at all?
Remove the fragile link. uv can fetch and manage its own Python interpreter per project. Passing --python 3.13 to uv init sidesteps the broken interpreter entirely and removes a fragile dependency from your stack.
